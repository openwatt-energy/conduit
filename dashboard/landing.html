What makes Conduit different

⚡

Dynamic credential loading

Device registry fetched from the OpenWatt backend API on startup and reloaded every 5 minutes. Add a dongle to the platform and it authenticates automatically — no restarts, no credential file edits. Supports P1M5 v1.0.47+, SmartStuff, and 1st-gen devices with hardcoded fallback credentials.

🚀

Direct InfluxDB writes speed

Telemetry data is parsed and written straight to InfluxDB with no intermediate REST API. The legacy stack required MQTT → mqtt2api → API → InfluxDB. Conduit collapses the entire pipeline into a single process. Zero network hops between parse and write.

⚙

Config-driven field mapping

P1M5 and SmartStuff field mappings live in configs/p1m5.json and configs/smartstuff.json. Add a new meter field without a single line of Rust — just add the OBIS code, target name, type, and optional scale factor. Compiled into the binary at build time for zero runtime overhead.

⛩

Multi-protocol parser

Handles three telemetry formats simultaneously: raw DSMR text (legacy dongles), JSON from v1.0.47+ firmware, and SmartStuff/BEPR JSON. Auto-detection by topic prefix and payload type. All parsed through the same pipeline into a unified InfluxDB schema.

🔒

Layered authentication

Attempts static device auth first (1st-gen devices with plain passwords), then falls back to SHA256-based auth (P1M5 firmware). Unknown P1M5 devices that pass password verification are accepted via fallback — dongles never get locked out while the registry sync catches up.

📝

Built-in observability

Live health dashboard with real-time connection counts, auth failure tracking, parse error rates, and InfluxDB throughput. GCP Cloud Monitoring alerts on dongle count, auth failures, and write errors. Docker log rotation caps disk usage at 60 MB.
